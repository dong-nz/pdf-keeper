# PDF Keeper v0.0.4

**Released 2026-11-05** · Windows (x64)

This release is a quality pass on the window v0.0.3 introduced: it fixes the rough edges people reported or measured — cut-off menus, soft thumbnails, misaligned controls, hard-to-read colors in the light theme — and tidies the spacing and wording until they follow one consistent set of rules. What the library stores and how it imports, finds, searches, sorts and opens your files is unchanged.

## What's different

**Thumbnails are sharp again.** Cover images are now generated much larger (640 px instead of 220 px), so a wide card shows a real picture instead of an enlarged, soft one. The first time you start this version, the app quietly rebuilds every thumbnail in the background — the progress bar shows it working, everything else stays usable while it runs, and it happens only once.

**Menus can't get cut off.** A menu or submenu longer than the window now stays inside the window and scrolls, and every entry is reachable with the keyboard. Before, a long category list in the Browse menu could hide categories past the window's bottom edge with no way to scroll to them.

**A card's cover stays inside the card.** The cover picture no longer crosses the card's own border at wide card widths; it fills the card's top area exactly.

**A missing file's row now offers Relink.** The row and card of a document whose file is missing show **Relink** in their action line, in the same order the right-click menu lists it. Before, you had to open the menu, the error message, or Details to reach it.

**`Ctrl+A` works.** Pressing `Ctrl+A` while you are not typing selects the documents currently shown on screen and opens the action bar; its "select all N matching" then extends the choice to the whole result set. This shortcut was described in the manual since the first release but was never actually wired up. Typing `Ctrl+A` inside a text field still just selects the text there.

**The favorite star looks like the other row actions.** The star button now has the same size, alignment and hover tooltip as the Details and Delete buttons beside it — before it was a smaller button with no tooltip.

**Toolbar icons sit in the middle of their buttons.** Every icon in the top bar was a few pixels off-center; they are centered now.

**No more arrow buttons on scrollbars.** The small up/down buttons that some systems drew at the ends of scrollbars are gone; the thin bar is unchanged.

**The list lines up.** Every row's file-size figures now end at the same right edge, regardless of how long a file name is. Rows and cards also keep a consistent 12 px margin from the window edges, aligned with the toolbar, so nothing touches the frame.

**The light theme is easier to read.** The blue, orange and red colors used for text in the light theme were too pale against their backgrounds (below the readability standard); they are darker now and meet it everywhere they appear as text. The dark theme was already fine and is unchanged.

**The progress bar actually animates.** During an import or thumbnail job the bar now slides to each new position instead of jumping.

**Loading placeholders match the real list.** The grey shapes shown while documents are loading now have exactly the size and position of the real rows, so the list no longer jumps when your documents appear.

**The Settings window shows where your library lives.** The *Library* section now displays the folder where the app keeps its index and thumbnails. It is shown for reference: the text can be selected and copied, but the location can't be changed and there is no folder button. Section headings are no longer in capital letters.

**A missing file is marked the same way everywhere.** The "file missing" flag on a row is now plain warning-colored text with the last-known path as its tooltip — the same treatment the Browse menu and the Settings window already used. Cards keep a small filled badge, since it sits on top of the image.

**Category counts are plain numbers.** The filled pill behind each count in the category manager is gone; counts are quiet, aligned numbers now.

**Small consistency fixes.** Menu and button labels no longer end in "…" (the progress messages "Importing…", "Checking files…" and "Generating covers…" keep theirs — they describe work happening, not something to open); every item in the Browse menu has its leading icon; the empty-library message shows `Ctrl+I` as little key graphics instead of plain text; and spacing throughout dialogs, toasts and progress rows was moved onto one consistent scale.

## Not in this version

- **Windows only.** macOS and Linux installers still come with a later release. Everything above was verified on Windows.
- **No full-text search.** Page contents are still not indexed — search covers titles, authors, notes and file names.
- **No language choice.** The app is English-only.
- **The library location is shown, not movable.** You can see where the index and thumbnails live, but you cannot move them, and there is no "open the folder" button.
- **The Select mode is still not remembered** between runs, on purpose.
- **No reading progress, grouping, series or subjects** — still deliberately out of scope.
- **Automatic titles and authors are still best effort**, and folder imports are still one-time actions with duplicates matched by exact location.
- **Cover thumbnails still need the helper library** that ships next to the app.

## Known limits in this build

- **The first start after updating rebuilds every thumbnail.** With a large library this takes a while and the progress bar shows it. It happens once; from the next start the new thumbnails are simply there.
- **`Ctrl+A` selects what is on screen, not the whole result set** — the action bar's "select all N matching" is the step that extends it to everything the current filter finds.
- **A favorited document still carries no permanent marker** in the list or the grid; the star shows in the actions line when you hover or focus the row.
- **Notes are still not shown on grid cards**; the editor remains their full view.
- **Rows are taller than in v0.0.2**, so a window holds fewer documents at once than it used to — the room is what the text and covers need.
