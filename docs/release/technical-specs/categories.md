# Categories — technical reference

**Since v0.0.1 · design updated in v0.0.2, v0.0.3 and v0.0.4** · Requirements: FR-02 (filter semantics MODIFIED in v0.0.2, DR-82), FR-07; v0.0.4: UI-24 (count presentation) · User guide: [features/categories.md](../features/categories.md) · Specs: [SPEC-v0.0.1-categories.md](../../specs/SPEC-v0.0.1-categories.md), [SPEC-v0.0.2.md](../../specs/SPEC-v0.0.2.md) §2 (FR-02), §3.2 (UI-09), §3.3 (UI-10); [SPEC-v0.0.3.md](../../specs/SPEC-v0.0.3.md) §2 (UI-03), §3.4 — decision DR-99; [SPEC-v0.0.4.md](../../specs/SPEC-v0.0.4.md) §3.15 — decision DR-116a

## Schema

- `categories(id, name UNIQUE COLLATE NOCASE)` — case-insensitive name uniqueness.
- `document_categories(document_id, category_id, PRIMARY KEY(document_id, category_id))` — many-to-many, FKs `ON DELETE CASCADE`.

## Commands

| Command | Behavior |
|---|---|
| `categories_list` | categories with live counts — `LEFT JOIN document_categories` + `GROUP BY`; counts computed in SQL, never cached client-side |
| `categories_create(name)` / `categories_rename(id, name)` / `categories_delete(id)` | delete cascades the join table only; documents are never touched (FR-02) |
| `library_set_document_categories(document_id, category_ids[])` | full replace from the editor modal |
| `library_bulk_categories(document_ids[], add[], remove[])` | add and remove in one transaction (FR-07) |

## Invariants

- A document may belong to zero or more categories (FR-02).
- **Any number of category ids may be active as a filter; the SQL is `EXISTS (SELECT 1 FROM document_categories dc WHERE dc.document_id = d.id AND dc.category_id IN (?, ?, …))` — the union, each document selected once** (FR-02 as modified in v0.0.2). With one id the statement is the shipped v0.0.1 behavior; with an empty list the clause is absent entirely, so the unfiltered path is unchanged.
- The category set composes with a saved-search mode and with search terms as `(A OR B) AND mode AND terms` — the mode and text clauses are the same ones searching.md documents, never a third path.
- Renaming never changes membership.
- `last_filter` grammar (settings): `all | favorites | missing` optionally followed by `&cats=<id>(,<id>)*`; the v0.0.1 single-category form `cat:<id>` remains valid input, so a pre-upgrade saved filter restores as that one category instead of being dropped (`is_valid_filter` / `is_valid_id_list` in `library/service.rs`).

## UI (`ui/src/`)

- **v0.0.2 (UI-09/UI-10): `Sidebar.svelte` and its 56px icon rail are deleted**, together with `ViewToggle.svelte`. Category CRUD now lives in `components/CategoriesDialog.svelte`, opened from Browse ▸ *Manage categories…* (420px, mounted through the shared `Modal` open-binding, DR-63; empty state "No categories yet."). It reuses the shipped `CategoryList.svelte` + `CategoryRow.svelte` (name order, live count chips, hover actions, context menu) and `NewCategoryField.svelte` — the components did not change, only their container. Filtering now happens in `BrowseMenu.svelte` (checkable multi-select Categories submenu) and was displayed by `FilterChips.svelte` until v0.0.3 removed the chips — the submenu's checked items are now the display (browsing-and-filtering.md); the active set is held in `lib/state/library.svelte.ts` as `filter.category_ids`, mutated only through `toggleCategory(id)` (adds/removes, then sorts ids ascending so a filter set has one canonical form) and reset by `selectMode("all")`. The full navigation design is documented in [browsing-and-filtering.md](browsing-and-filtering.md).
- *(v0.0.1, removed in v0.0.2)* `Sidebar.svelte` → `CategoryList.svelte` → `CategoryRow.svelte` as a fixed 264px panel (`--side-width`, global `border-box` making the declared width exact) collapsible by its chevron to a 56px icon rail (`--side-rail`): labels, counts, the section label, the new-category field, category row names and chips hidden in the rail, category rows icon-only, zero horizontal overflow (DR-61). Collapse state was component-local and never persisted.
- `NewCategoryField.svelte`: the "+ New category" field (unchanged in v0.0.2, now rendered at the top of the Categories dialog); Enter creates; a duplicate-name `AppError` reopens the field with an inline error and the typed text preserved (fixable input errors never surface as toasts).
- Rename: context menu or hover action → `RenameCategoryDialog.svelte` — prefilled field, duplicate name → inline error in the open dialog, commit through `categories_rename`, Discard closes. (The spec's original inline-input/`F2` design was superseded by the dialog — deviation recorded in DR-64.)
- Delete: context menu or hover action → `DeleteCategoryDialog.svelte` — confirmation stating documents keep their files; Discard / Delete category. Both dialogs follow the `DeleteDialog` open-binding pattern (`open = $state(true)` + `bind:open` + `$effect → ondone`) — a bare `<Modal>` mounted from `{#if}` renders closed (DR-63).
- `BulkBar.svelte` (visible when the selection is non-empty) → `CategoryPickerModal.svelte`: two-pane Add/Remove checkbox list pre-ticked from current membership; confirm calls `library_bulk_categories` once. Verified: the applied result is shown by the live counts updating in the Categories dialog and the Browse submenu — the spec's "bar reports applied counts" toast was not built (deviation recorded here per Rule 7; no requirement demands it). Since v0.0.3 no row chips exist to update (below).
- `CategoryChips.svelte` in rows/cards — **deleted in v0.0.3** (UI-03 as modified). It rendered at most 3 chips plus a `+N` overflow on a row and a card, with the full set only in the editor; its only two callers were `DocumentRow` and `DocumentCard`. Membership is now shown where it is acted on: the editor's checkbox list and `CategoryPickerModal`. `DocumentDto.categories` is unchanged (DR-51) — Details, the picker and the assignment flows read it, and a per-window extra query would be a second data path (R1.6). Live counts in the Categories dialog and in the Browse submenu are unchanged.
- **v0.0.4 (UI-24, §3.15, DR-116a): the manager's count is quiet text.** `CategoryRow.svelte` renders the live count in `.cat-count.tabular` — secondary text with tabular figures, transparent ground, no border, no pill. The `.chip` / `.chip-accent` rules (the pill's styling — one real consumer, one with none) were deleted from `base.css`; a source test (`chip-cutover.test.ts`) fails if the removed classes return or the count re-adopts a chip element. The count's data path (`categories_list` SQL counts) is unchanged; UI-10's requirement text ("lists every category with its live count") was never a pill.

## Change history

- 2026-11-03 (v0.0.1) — First shipped. Migrated from SPEC-v0.0.1-categories.md, corrected to the verified code: no post-bulk applied-count toast (chips/counts are the feedback); sidebar also carries a Missing saved-search row (missing-files-relinking.md).
- 2026-11-03 (v0.0.1, pre-Ship fix DR-61) — Sidebar rail corrected to the §5.3 design after a user-reported horizontal scrollbar: exact 264px / 56px-rail widths (tokens were defined but never applied — the grid sized to content), and rail hiding extended to child-component DOM via `:global()` (category row names + count chips). Smoke flow `flowSidebarRail` asserts both widths and zero horizontal overflow.
- 2026-11-03 (v0.0.1, pre-Ship fixes DR-62/DR-63/DR-64) — Rail hover no longer reveals the hidden actions or the scrollbar (hiding rules cover the `:hover`/`:focus-within` variants that out-ranked the plain rule). Category rename/delete dialogs — previously mounted closed and unreachable in every sidebar state — became real components (`RenameCategoryDialog`, `DeleteCategoryDialog`) following the `DeleteDialog` open-binding; verified end-to-end from the rail. The rename/delete design deviation (dialog instead of the spec's inline input/`F2`) was raised and adopted by the user (DR-64); the feature spec carries MODIFIED markers.
- 2026-11-04 (v0.0.2 — FR-02 MODIFIED, UI-09, UI-10; DR-82, DR-68) — **Filter semantics became a multi-select union.** `Query` carries `category_ids: Vec<i64>` and the query builder emits one `EXISTS (… dc.category_id IN (?, …))` clause: bound per id, no clause at all when the list is empty (the unfiltered statement is byte-identical to v0.0.1), one row per document whatever the number of matches. `last_filter` gained `&cats=<id>(,<id>)*` while `is_valid_filter` still accepts the v0.0.1 `cat:<id>` form, so a pre-upgrade filter restores as that one category. **The sidebar and its icon rail were deleted** (`Sidebar.svelte`, `ViewToggle.svelte`): CRUD moved into `CategoriesDialog.svelte`, which reuses `CategoryList` / `CategoryRow` / `NewCategoryField` / the rename and delete dialogs unchanged; filtering and its visible state moved to `BrowseMenu.svelte` + `FilterChips.svelte` (see [browsing-and-filtering.md](browsing-and-filtering.md)). Verified by `query.rs::several_active_categories_select_the_union`, `service.rs::last_filter_grammar_accepts_the_new_form_and_the_legacy_one`, and the smoke flows `flowCategoriesMulti` (union asserted against each single-category result set, the shared document counted once, status counts agreeing with the union, exactly one chip per active filter) and `flowCategoryCrud`. Design sections above updated to the code as released; the removed sidebar design is kept as a marked historical entry.
- 2026-11-04 (v0.0.3 — presentation only, UI-03 MODIFIED; DR-99) — **`CategoryChips.svelte` deleted**: rows and cards no longer show membership, so the "3 chips + `+N`" truncation and the editor-only full set became one thing — the lists where categories are actually assigned (Details, `CategoryPickerModal`). The union filter, the `&cats=` grammar, the manager dialog, the picker and `library_bulk_categories` are the v0.0.2 behavior unchanged; `DocumentDto.categories` still ships per document (DR-51), which is what keeps the editor and picker free of a second query path (R1.6). Verified by `flowRowDesign` (no badge on a row at all), `flowCategoriesMulti` (union result sets, checked items in the Browse submenu) and `flowCategories`' picker steps.
- 2026-11-05 (v0.0.4 — UI-24 §3.15, DR-116a) — Presentation only: the categories manager's live count changed from a filled pill (`.chip.tabular`) to quiet secondary text with tabular figures; the `.chip` / `.chip-accent` rules were deleted with their only consumer path, guarded by `chip-cutover.test.ts`; the *Manage categories* label lost its ellipsis (UI-20). Schema, commands, union semantics, the `&cats=` grammar, the picker and the bulk call are unchanged. Verified by `flowQuietCounts` (AC-46) inside the existing CRUD flow.
