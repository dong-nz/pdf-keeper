# Import — technical reference

**Since v0.0.1 · design updated in v0.0.2, v0.0.3, v0.0.4 and v0.0.7** · Requirements: FR-10 (MODIFIED in v0.0.2; further MODIFIED in v0.0.7 — the app stays responsive during an import, §3.20, DR-233), FR-11 (parent FR-01, NFR-02, NFR-07), UI-14 (ADDED in v0.0.3); v0.0.4: UI-20 (import labels without ellipsis) · User guide: [features/importing-pdfs.md](../features/importing-pdfs.md) · Specs: [SPEC-v0.0.1-importing-pdfs.md](../../specs/SPEC-v0.0.1-importing-pdfs.md), [SPEC-v0.0.2.md](../../specs/SPEC-v0.0.2.md) §2 (FR-10); [SPEC-v0.0.3.md](../../specs/SPEC-v0.0.3.md) §3.5 — decision DR-94; [SPEC-v0.0.4.md](../../specs/SPEC-v0.0.4.md) §3.9 — decision DR-110; [SPEC-v0.0.7.md](../../specs/SPEC-v0.0.7.md) §3.20 — decision DR-233

## Commands (Tauri)

| Command | Signature | Behavior |
|---|---|---|
| `library_import_paths` | `(paths: Vec<String>, category_ids: Vec<i64>) -> ImportResult` | Imports the given `.pdf` paths; non-`.pdf` and directories are reported as skipped (`not_pdf`), never silently dropped. `category_ids` is the whole active filter set (v0.0.2; was `category_id: Option<i64>`) — an empty vector assigns nothing |
| `library_import_folder` | `(dir: String, category_ids: Vec<i64>) -> ImportResult` | Walks `dir` for `*.pdf` (`std::fs::read_dir`, one-time bulk; nothing is watched) |

`ImportResult { imported: u32, skipped: Vec<Skipped> }` where `Skipped` is typed (`already_in_library` | `not_pdf`). Progress is streamed on the `library_job_progress` event (`{kind: "import", processed, total, done}`); the command returns once rows are committed — cover generation is queued separately (covers.md), so import never waits for rendering (NFR-02).

## Pipeline (`src-tauri/src/library/service.rs`)

**As re-cut in v0.0.7 (§3.20, DR-233).** The released single-transaction pipeline held the library's one Mutex-guarded connection for the whole import while it extracted metadata per file — synchronous commands (search, categories, settings) blocked on that mutex for the run, and progress was emitted only per 500-file chunk, so imports of ≤ 500 files showed no progress at all. The shipped pipeline:

1. Candidates: filter paths to `.pdf` (non-`.pdf` → typed `not_pdf` skips), `normalize_path`, metadata (size/mtime) per file — **outside the connection**.
2. **Chunked work:** `CHUNK: usize = 25`; for each chunk: `pdfmeta::extract` per file (outside the lock; a per-file extraction failure falls back to the filename silently — never fails the batch), then `import_chunk` inside **one short transaction** (`db.with_raw`): INSERT OR IGNORE + join rows for the active categories. The connection is held only for the write, never for extraction — synchronous commands keep answering between chunks (AC-101).
3. **Duplicates (FR-11):** `documents.path UNIQUE` + `INSERT OR IGNORE` — ignored rows are collected as `already_in_library` skips. Semantics unchanged.
4. **Auto-assignment (FR-10, v0.0.2):** `validate_categories` checks **every** id before the first chunk writes (`AppError::CategoryNotFound`); join rows are written per chunk inside the same transaction as that chunk's documents — one assignment set per import. An empty slice assigns nothing.
5. **Progress:** one `library_job_progress` `{kind: "import", processed, total, done}` event opens the run before any file is processed (`processed: 0`), one per chunk, a final `done` event closes it — emitted outside the lock. Visible from start to completion for imports of any size (AC-101).
6. Cover jobs enqueued to the cover queue (covers.md) as rows commit; the command returns once the last chunk is committed — import never waits for rendering (NFR-02).

## UI (`ui/src/`)

- `components/ImportButton.svelte` — **deleted in v0.0.3** (UI-14; R7.4). It was a split control: primary opened the native multi-select picker (`tauri-plugin-dialog`), the caret opened a hand-written menu with "Import folder…", and while a job ran both halves were disabled with the label "Importing…". Its whole role moved into the search field, below.
- `components/SearchBox.svelte` (v0.0.3, UI-14) — the field keeps its leading magnifier and carries, at its trailing end behind a 1px `--border-strong` divider, the import control: a plus icon button (`plus` path already in `components/icons.ts`; no new icon) with the accessible name and tooltip "Import". The clear button and the plus share that slot — clear while the field holds text, plus otherwise — so a control is never hidden by a state the user can't see. The plus opens a two-item menu, *Import files* and *Import folder* (labels without the ellipsis since v0.0.4, UI-20), reusing the shipped menu chrome, and both call the existing `importFlow` functions (`pickFilesAndImport`, `pickFolderAndImport`). `Ctrl+I` and the drag-and-drop path are untouched. The busy state moved with the control: the plus is disabled while `feedback.job !== null`.
- `App.svelte` subscribes to `tauri://drag-enter` / `drag-leave` / `drag-drop` (real FS paths; `drag-over` is not subscribed — enter/leave is sufficient for the overlay) and renders the full-window drop overlay. Since v0.0.2 its second line names **every active category** (`drop.toCategory` = "Adds to {categories}", built from `filter.category_ids`) — in v0.0.1 it named the single selected category.
- `lib/importFlow.ts` — picker calls; `state/library.svelte.ts#importPaths` — invoke + result reporting: toast "Imported N PDFs" plus, when `skipped` is non-empty, a second toast "M files skipped (already in library)". The spec's single-toast-with-expandable-body detail was not built; two plain toasts carry the same information (deviation recorded here per Rule 7).
- `ProgressBar` in the status bar renders `library_job_progress`; the busy gate (Rescan and Import disabled) stays closed until the cover queue drains (FR-15; verified: gate opens only after covers complete).

## Invariants

- Import never copies/moves/renames user files (FR-01).
- A failed per-file metadata step never fails the batch (fallback path).
- The same path cannot exist twice in `documents` (UNIQUE).
