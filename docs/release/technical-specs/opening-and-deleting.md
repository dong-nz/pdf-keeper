# Opening & deleting — technical reference

**Since v0.0.1 · design updated in v0.0.2 and v0.0.3** · Requirements: FR-08, FR-09, UI-03 (MODIFIED in v0.0.3), UI-05 · User guide: [features/opening-and-deleting.md](../features/opening-and-deleting.md) · Specs: [SPEC-v0.0.1-opening-and-deleting.md](../../specs/SPEC-v0.0.1-opening-and-deleting.md), [SPEC-v0.0.2.md](../../specs/SPEC-v0.0.2.md) §2 (D1), §3.7; [SPEC-v0.0.3.md](../../specs/SPEC-v0.0.3.md) §2 (UI-03, selection semantics), §3.4, §3.9 — decisions DR-99, DR-106

## Opening (FR-08)

- `resolve_open_target(id)` (`library/service.rs`): returns the stored path; a `missing` document yields a typed `AppError` (no silent failure).
- The command layer hands the path to `tauri-plugin-opener` (`open_path`) — the OS default handler opens the file; PDF Keeper never renders PDFs itself.
- **Activation (as fixed in v0.0.2, DR-66):** `ondblclick={() => library.open(id)}` on both `DocumentRow.svelte` and `DocumentCard.svelte`; **a single click only focuses or selects** (`rowClick` / `cardClick` — plain click focuses the row, Shift/Ctrl-click toggles selection, the checkbox is the other selection path), `Enter` on the focused row and the row's Open action activate through the same `library.open` store path. The shipped v0.0.1 code opened on single click, contradicting the released FR-08 text; the code was aligned to the spec rather than the spec to the code, and the smoke suite gained the negative case (a single click must not open).

## Deleting (FR-09)

- Two commands: `library_delete_document(ids)` (library row only; file stays on disk) and `library_delete_document_and_file(ids)`.
- `DeleteDialog.svelte` is the single confirmation surface (row action, context menu, bulk bar, and the editor's Delete… all route here). Title is plural-aware (`delete.title.one/.other`); body states files are untouched unless the user picks **Delete with files**.
- File-deletion failure (DR-50b): rows stay intact, an error toast offers a **retry** action bound to `delete(ids, true)`. `library.delete` returns success so callers (the editor) can distinguish completed deletion from cancel.
- Deletion removes cover-cache entries with the row (orphan sweep also catches leftovers at startup).

## Selection & actions (UI-03, UI-05)

- Context menu and row buttons render the same action list (`lib/actions.ts`) — parity is structural, not duplicated (R7.4/R4.7). Closing the menu with Esc must not clear the selection (§5.2).
- **The selection checkbox is gone (v0.0.3, UI-03 as modified).** `DocumentRow.svelte` no longer renders a checkbox and `DocumentCard.svelte` no longer renders the checkbox overlay; selection is the row's own state, reached by `Space` on the focused row, by `Ctrl`/`Shift`-click, and — in Select mode — by a plain click (selecting-documents.md). `BulkBar.svelte` is untouched: it appears whenever a selection exists.
- **The row's shown action set is `favorite, details, delete`** (`ROW_ACTION_IDS` in `lib/actions.ts`), rendered in one actions line at the row's trailing end, shown by the shipped `.row:hover` / `:focus-within` rule and never permanent — so no star, no category badge and no checkbox is on screen at rest. `StarButton.svelte` is the same component, now called from that line. The Details action's glyph changed from `tag` to the `info` path already in `components/icons.ts`; `lib/actions.ts`'s category and bulk entries keep `tag` (they act on categories, and the glyph is the same one the category actions use).
- `CategoryChips.svelte` — **deleted in v0.0.3**: it had exactly two callers, `DocumentRow` and `DocumentCard`, and no other component renders membership. `DetailsModal` and `CategoryPickerModal` render it through their own code, and `DocumentDto.categories` is unchanged (DR-51): a per-window extra query would be a second data path (R1.6).
- Row keyboard contract unchanged: roving tabindex, `Space` toggles selection, `Enter` opens, `Delete` opens the confirmation. What changed is only what a plain pointer click does (UI-18, selecting-documents.md).

## Test mapping

| Layer | Coverage |
|---|---|
| `src-tauri/src/library/` tests | open target resolution incl. missing → typed error; delete row-only vs delete-with-file; file-delete failure keeps rows |
| `scripts/ui-smoke.mjs` | Enter opens a present file via the OS (no failure surfaced); confirmation dialog cancel/confirm paths; editor Delete… cancel keeps the document, confirm removes it; selection → bulk delete. **v0.0.2 (AC-12):** `flowOpen` counts `app_open_document` calls at the real command boundary — a single click selects the row and opens nothing (zero calls), a real double-click activates the document, and Enter on the focused row still opens. The flow carries a fallback (dispatch a synthetic `dblclick` and mark the native check skipped) for drivers whose pointer action chain does not produce a native double-click; the verified run used the native path with nothing skipped. **v0.0.3:** the same flow now asserts a single click opens nothing **and selects nothing** in browse mode (AC-12 / AC-30); `flowRowDesign` asserts a row renders no checkbox and no category badge, measures the 64 px row with its 45×64 cover, the actions line hidden at rest and shown on hover and keyboard focus, and the `info` glyph on Details; `flowMetadata`'s nested-delete checks cover the editor → delete handoff and the UI-02 discard step; the §5.2 rule that closing a dialog with Esc keeps the selection is asserted in `flowOpen`'s dialog steps, and the counterpart — Esc clears the selection when nothing is open — in `flowSelectMode` (DR-106) |

## Change history

- 2026-11-03 (v0.0.1) — First shipped. Migrated from SPEC-v0.0.1-opening-and-deleting.md, corrected to the verified code: plural-aware confirmation title; editor Delete… handoff added during verification (UI-02); `delete` returning success for caller-side outcome handling.
- 2026-11-04 (v0.0.2 — defect D1, DR-66) — **Activation aligned to the released FR-08 text.** The shipped build opened a document on a single click; rows and cards now open on double-click only, while a single click focuses or selects (Shift/Ctrl-click selection unchanged) and Enter / the Open action keep working through the same store path. No requirement changed and no backend change was involved. Verified by the AC-12 negative case added to `flowOpen` (single click produces no command call; double-click and Enter do).
- 2026-11-04 (v0.0.3 — UI-03 MODIFIED, D1's alignment MODIFIED; DR-99) — **The row lost its permanent furniture**: the selection checkbox (list and card), the category badges (`CategoryChips.svelte` deleted — its only two callers were the row and the card), and the persistent star; the shown action set became `favorite, details, delete` in one hover/focus-revealed line, with Details taking the `info` glyph. **What a plain click does is now a mode** (UI-18): in the default browse mode a click only focuses the row, in Select mode it toggles selection — `FR-08`'s activation rule (double-click / Enter / Open) is untouched in both modes, and `Space`, `Ctrl`-click and `Shift`-click ranges are shared code, not re-implemented. Rationale recorded in the spec: with the checkbox gone, a click that always selected would build selections users never asked for. `DocumentDto`, the delete commands and the confirmation dialogs are unchanged. Verified by `flowRowDesign`, `flowSelectMode` and the AC-12 assertion updated to "opens nothing **and** selects nothing".
