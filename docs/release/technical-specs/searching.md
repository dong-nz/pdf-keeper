# Search — technical reference

**Since v0.0.1 · design updated in v0.0.2, v0.0.3 and v0.0.8** · Requirements: FR-03 (parent NFR-01, NFR-02, NFR-07), UI-16 (ADDED in v0.0.3); v0.0.8: UI-43 scope (Reading), UI-42 vocabulary · User guide: [features/searching.md](../features/searching.md) · Specs: [SPEC-v0.0.1-searching.md](../../specs/SPEC-v0.0.1-searching.md), [SPEC-v0.0.2.md](../../specs/SPEC-v0.0.2.md) §3.2 (the shared builder's filter clause), [SPEC-v0.0.3.md](../../specs/SPEC-v0.0.3.md) §3.5 — decision DR-94; [SPEC-v0.0.8.md](../../specs/SPEC-v0.0.8.md) §3.2, §3.7

## Index (`src-tauri/src/library/`)

- SQLite **FTS5** virtual table `documents_fts(title, filename, author, notes)`, external-content keyed to `documents(rowid)` (rusqlite bundled, DR-14).
- INSERT/UPDATE/DELETE triggers on `documents` keep the index consistent inside the same transaction as every mutation — no reindex step.
- Query tokens compile to FTS5 prefix syntax (`tok*`); multiple tokens AND-combine (`library/query.rs`).

## Query composition — `library_search(query, category_ids, favorites_only, missing_only, sort, dir, sort_secondary, offset, limit)`

1. FTS MATCH on the compiled query, or all rows when the query is empty.
2. AND with the **category id set** (v0.0.2: `category_ids: Vec<i64>` → one `EXISTS (… dc.category_id IN (?, …))` clause, the union, no clause when the list is empty) and with the favorites/missing mode — filters combine with AND semantics: `(category A OR category B) AND mode AND terms` (categories.md, FR-02 as modified).
3. `ORDER BY d.favorite DESC, <whitelisted primary> <dir>[, <whitelisted secondary> <dir>], d.id ASC` — favorites pinned first under every sort (`query.rs::parse_sort` / `parse_sort_secondary` whitelist sort/dir/secondary; no free-form SQL from user input, R2.2; sorting-and-views.md).
4. Windowed slices only (NFR-01): the UI requests slices as it scrolls. `library_ids` carries the same filter and sort parameters (the bulk-selection id set must describe the same result set).

Latency: AC-02 asserts < 100 ms at 10 000 documents (`service.rs` test with timing assertion). Out of scope: PDF body/full-text, fuzzy matching, stemming beyond FTS5 defaults. Search semantics themselves are unchanged in v0.0.2 — only the shared builder's category clause and ORDER gained the second key.

## UI (`ui/src/`)

- `components/SearchBox.svelte` — input with immediate local echo; queries go through `lib/debounce.ts` (150 ms, NFR-07); a clear (×) button appears when non-empty and, since v0.0.3, shares its slot with the import control (importing-pdfs.md); `Esc` while focused clears the search and stops propagation (innermost-consumer rule, §5.2); `Ctrl+F` focuses + selects via the global handler, and Ctrl+F *inside* the box selects the text locally (DR-57). Since v0.0.3 the field's placeholder is derived (below) and its accessible name is the fixed catalog key `search.label` = "Search" — deliberately not the placeholder, which changes with state.
- `lib/searchScope.ts` (v0.0.3, UI-16) — a pure function `searchPlaceholder(filter, total, categories) -> string`: no DOM, no store, so every case is unit-testable against fixture counts. The six cases UI-16 names are exhaustive: no filter → `search.placeholder.all` with `formatCount(total)`; one category → its **name**; several → `{n} categories`; Favorites → "Search in Favorites"; Missing alone → "Search in Missing"; Favorites with categories → "Search in Favorites · …". Combinations the requirement does not name (Missing with categories) resolve to the category case they are a superset of. Ids that no longer name a category are dropped — the same validation `App.svelte` applies to a restored `last_filter`. Plurals go through the existing `tp` / `Intl.PluralRules` path, counts through `formatCount`. The result is display-only: never part of the query, never persisted, and typing hides it natively.
- `state/library.svelte.ts` — `#querySeq` stale-response guard: superseded query results are discarded, never rendered; a result set is assigned in one write (R4.3) and the scroll resets. Every filter change (search text, category set, mode, sort) goes through the single `setFilter` path that re-queries from offset 0.
- `components/FilterChips.svelte` — **deleted in v0.0.3.** From v0.0.2 to v0.0.3 it was the visible state of the whole filter (a chip per active category id, one for the Favorites/Missing mode, each removable through `setFilter`); the Browse menu's checked items now carry that role ([browsing-and-filtering.md](browsing-and-filtering.md)). The "category no longer exists" case is now a toast (`feedback.svelte.ts`, `error.categoryGone`), not a chip label. Status-bar counts stay library-wide regardless of filters (FR-15 invariant). No matched-term highlighting — still not built (needs backend match offsets).
- `EmptyState` variant "No documents match …" with a Clear action.

## Change history

- 2026-11-03 (v0.0.1) — First shipped. Migrated from SPEC-v0.0.1-searching.md, corrected to the verified code: `missing_only` is part of the same query composition; SearchBox-local Ctrl+F select added (DR-57); debounce verification moved to the Vitest pure-logic scope (DR-57).
- 2026-11-04 (v0.0.2 — builder touched by FR-02 MODIFIED and FR-13 MODIFIED) — No change to search semantics or to the FTS index. The shared builder gained `category_ids: Vec<i64>` (one `EXISTS … IN (…)` union clause, absent when empty) and an optional whitelisted secondary key in the ORDER clause, and `FilterChips.svelte` became the visible state of the whole active filter rather than of the search text alone. Verified through the categories and sorting test mappings; `flowCategoriesMulti` covers search terms combined with two active categories.
- 2026-11-04 (v0.0.3 — UI-16) — The search field gained a scope-naming placeholder, derived by the new pure `lib/searchScope.ts` from the filter state and the library counts, with the input's accessible name fixed as `search.label` so it cannot shift with state. `FilterChips.svelte` was deleted (its role moved to the Browse menu's checked items, browsing-and-filtering.md) and the import control took the field's trailing slot (importing-pdfs.md). **The FTS index, the query builder, the debounce and the stale-response guard are untouched** — the search semantics are byte-for-byte the v0.0.2 ones. Verified by `searchScope.test.ts` (the derivation) and `flowSearchField` (what the app actually renders); AC-02's timing assertions were re-run unchanged against 10 000 documents.
- 2026-11-10 (v0.0.8 — UI-43 scope; UI-42 vocabulary) — **Search semantics, the FTS index and the builder's text clauses are unchanged.** The shared builder's tag clause carries the renamed table/ids (`EXISTS … document_tags … tag_id IN (…)` — [tags.md](tags.md)), and the mode composition gained the `reading_only` arm beside `favorites_only` / `missing_only` ([reading-collection.md](reading-collection.md)) — the same single query path, no third one. The scope-naming placeholder follows: `searchScope.ts` composes "Search in Reading", "Search in {name}", "Search in {count} tags", "Search in Favorites · {count} tags" (the same composition rules, renamed strings); `searchScope.test.ts` covers the Reading scope. Verified by the unit tests and `flowReading`'s search-composition steps (AC-103).
