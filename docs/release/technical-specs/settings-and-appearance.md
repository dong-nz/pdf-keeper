## Stored settings (`src-tauri/src/library/`)

`SettingsDto` (`library/mod.rs`): `view`, `sort`, `dir`, `sort_secondary`, `grid_columns`, `theme`, `last_filter` — all strings, defaults applied on read. `theme` was added in v0.0.3; the other keys are the v0.0.2 grammar unchanged (categories.md, sorting-and-views.md).

- `set_setting` rejects an unknown key (`Unknown setting: …`) and a value outside that key's grammar (`Invalid value for …`) — `Validation` errors, never a silent write. `theme` accepts exactly `"system" | "light" | "dark"` (`is_valid_theme`).
- A **stored** value that fails validation is discarded on read and the default applies: `get_settings` filters `theme` through `is_valid_theme` and falls back to `"system"`, so a corrupt row is never a theme and never an error the user can see. `grid_columns` keeps its own grammar (`"auto"` or an integer 2–10).
- Commands are thin wrappers (R1.2): `app_get_settings() -> SettingsDto`, `app_set_setting(key, value)`, `app_about() -> AboutDto { name, version }` read from `app.package_info()` — the version is never a string written in the frontend. **v0.0.4 (UI-21, DR-111): `app_data_dir(app) -> Result<String, AppErrorPayload>`** — a field read of the same `app.path().app_data_dir()` that `lib.rs` resolves at startup to place `library.db` and `covers/`; no service module, no business logic, no settings key. Whitelisted in `ui/src/api.ts` alongside the rest (`app_get_settings`, `app_set_setting`, `app_about`, `app_data_dir`); `api.ts`'s `COMMANDS` list and the Rust router are held in step by `tests::command_router_matches_the_ui_command_client` (AC-41).
- Writes reach the store through the **batched flush** introduced in v0.0.2 (sorting-and-views.md): `lib/state/settings.svelte.ts` collects changed keys in `#pending`, one debounced `#flush` writes each key once with its last value, `flushNow()` forces it. A theme change and a view change made together therefore land as separate per-key writes, not one interleaved value.

## Color ramp (`ui/src/lib/theme.ts`, `ui/src/lib/design-tokens.css`)

- The stored setting is a **choice**; the document root carries a **concrete** ramp. `applyTheme(choice)` resolves it — `"system"` → `matchMedia("(prefers-color-scheme: dark)")`, otherwise the explicit value — and writes `document.documentElement.dataset.theme`. That is why `design-tokens.css` needs exactly two blocks (the light default and `[data-theme="dark"]`) instead of duplicating the dark palette for the OS case and the override case (DR-101).
- `main.ts` calls `applyTheme("system")` synchronously before mount, so the first paint follows the OS with no stored value and no flash; `App.svelte` re-applies the stored choice once settings load.
- `onSystemThemeChange(handler)` keeps live OS following while the choice is `"system"` — the behavior a plain `prefers-color-scheme` media block gave for free — and returns the detach function so the listener is removed with the component.
- Each ramp block declares `color-scheme: light` / `color-scheme: dark`, so the parts the OS draws (scrollbars, form fields, native scroll areas) follow the chosen ramp rather than the computer's setting — the custom scrollbar chrome itself is already token-colored (UI-11, the-app-window.md).
- **v0.0.4 (D11, §3.12, DR-120): light-ramp text-role contrast.** Measured from the token hexes, the v0.0.3 light ramp put accent-, warning- and danger-as-text below 4.5:1 on the surfaces they actually render on (accent 3.81:1 on white; warning on its own 12 % tint 3.76–4.25:1; danger on its tint 3.90–4.41:1). The light ramp was retokenized to the approved values: `--accent #2f6ae0` / hover `#2559c2`, `--warning #a35d16` / hover `#8f5214`, `--danger #a44a2e` / hover `#92402a`, tints re-derived from the new hues at the same 12 % alpha; text sitting on its own tint takes the hover value. The dark ramp already cleared 4.5:1 everywhere and is unchanged. Which elements use which role did not change — active controls, active menu items, the starred star, the selection count, the missing marker and error text keep their roles. A permanent Vitest test (`design-tokens.test.ts`) computes WCAG contrast from the stylesheet for every text role against its exact ground, tint blends included, both ramps (AC-43); the smoke flow reads the resolved `--accent` from the running app in both ramps.
- **v0.0.6 (UI-32, §3.6, DR-139/DR-145): the dark ramp re-authored to the Dracula Classic palette.** The `[data-theme="dark"]` block was rewritten token by token to the official palette: surfaces `#282a36` (Background) / `#343746` (Background Light — menus, modals, hovered rows) / `#424450` (Background Lighter — control/card/category hover) / `#44475a` (Selection); borders take Background Light and Selection; text takes Foreground `#f8f8f2` with secondary at 72 % and tertiary at 65 %; accent takes Purple `#bd93f9` with the ANSI BrightBlue `#d6acff` hover and `--text-on-accent` = Background; warning Orange `#ffb86c`, success Green `#50fa7b`; the scrollbar thumb takes Selection. **Measured substitutions** (DR-145 — every one a Dracula-documented variant chosen by measurement, recorded in the stylesheet comments): text-tertiary 55 % measured 4.01 on the card-hover ground, 65 % is the documented variant that clears; accent-quiet 16 % measured 4.02 and 3.71, 8 % chosen for margin (4.58 on the binding ground); danger: Red `#FF5555` (3.75/3.07) and BrightRed `#FF6E6E` (4.33/3.54) both fail the UI-palette grounds, so danger takes ANSI BrightMagenta `#ff92df`; the dark warning tint grounds clear 4.5:1 at the base value, so `--warning-hover` resolves to the base there (the token exists in both ramps — components reference it, and an undefined token is the D10 failure mode); danger-quiet 16 % measured 4.32, 12 % clears at 4.68. **The light ramp is byte-identical to v0.0.5** (asserted against the v0.0.5 Ship commit's file, AC-70); the theme control, the `theme` setting key, resolution and `system` handling are unchanged (UI-17 untouched). Enforcement: `design-tokens.test.ts` asserts every dark token equals the §3.6 mapping or its recorded substitution pair, and the pair contrast table; `flowDarkRamp` measures every text role ≥ 4.5:1 on its exact rendered ground in the running app (AC-71) and asserts the hover/selection surfaces render the Background Light / Selection tokens.

## Entry points

Three controls reach the same settings store; none holds state of its own (R1.6):

- **`components/SettingsMenu.svelte`** (UI-13) — the toolbar control at the right end, left of the window buttons. Items in order: the theme submenu, whose trigger shows the currently chosen theme (icon + label, `data-active` on the matching item — DR-102b) and offers System / Light / Dark; **Settings** (mounts the dialog; label without the ellipsis since v0.0.4, UI-20); **About PDF Keeper** (same). The theme list and its icons (`monitor`, `sun`, `moon`) are local to the menu; `current` is derived from the store, so the trigger cannot disagree with the setting.
- **`components/SettingsDialog.svelte`** (UI-08/UI-15) — a second entry point to the same state, not a copy of it. Appearance section: theme radiogroup, list/grid radiogroup, and the columns control (Auto plus the `-`/count/`+` row) — the same `settings.setTheme` / `setView` / `setGridColumns` calls the View menu makes, and the same derived effective column count from `lib/state/layout.svelte.ts`, so a change made in either place is live in the other without a reload (AC-29). Library section: `library.counts.total / favorites / missing` (the `status_updated` payload, status-feedback.md) and the name/version from `app_about` — and **since v0.0.4 (UI-21)** a *Location* row showing the `app_data_dir()` path, read once when the dialog opens, rendered as selectable text (`user-select: all`), with no open-folder action and no edit path (AC-41). **v0.0.4 (UI-22, §3.13):** `.section-title` drops the uppercase transform, the wide letter-spacing and the 11 px size — headings render at the dialog's own 13 px / weight-600 sentence-case scale, separated by the hairline rule; catalog strings byte-identical (AC-44). **v0.0.4 (UI-27, §3.18):** the dialog's section gaps and margins move onto the shared 4/8/12/16/24 scale (16 px between sections) — measured, not asserted by eye (AC-49, mapped with the other UI-27 surfaces in status-feedback.md). Mounted through the shared `Modal` open-binding (DR-63), focus-trapped, closes with Esc or its close button.
- **`components/AboutDialog.svelte`** (UI-12, since v0.0.2) — name and version from `app_about`, nothing else; the same `Modal` pattern.

## Not in this release

No language setting (the app is English-only; the catalog in `ui/src/lib/i18n/` is not user-selectable — Vietnamese is named as the target of a later release, DR-114). The Library section shows counts, the name, the version and — since v0.0.4 — the library location as read-only text: no move of the database or cover cache, no folder picker, no open-in-file-manager action (DR-111; the configurable variant stays a candidate with its recorded cost). The Select-mode flag is deliberately absent (selecting-documents.md): it is session state and has no settings key.

## Invariants

- The theme choice persists; the resolved ramp is derived, never stored. `system` is both the default and the way to hand the decision back to the OS.
- One settings store, several controls. Any control that shows a setting reads it from the store and writes through the store's methods — no component keeps a local copy, no control can display a value the backend would reject (the frontend's option lists are the same whitelists the backend validates).
- An invalid stored value never reaches the UI as an error and never becomes a setting.

## Change history

- 2026-11-04 (v0.0.2 — UI-12 ADDED, DR-79) — First shipped as the About dialog: name and version read from `app.package_info()` through `app_about`, mounted through the shared `Modal` open-binding. No settings change.
- 2026-11-04 (v0.0.3 — UI-13, UI-17 ADDED; Settings dialog as a second entry point; DR-101, DR-102, DR-102b) — **The theme became a stored setting** (`theme` in the grammar, validated to `system | light | dark`, corrupt rows falling back to `system`) and **the ramp became a resolution of it**: the choice is stored, `data-theme` carries the concrete value, the stylesheet keeps two blocks, and `color-scheme` on each block carries the choice to the parts the OS draws. The Settings menu and the Settings dialog are new controls over the **same** store the View menu already used — verified by asserting both directions of a view change in the running app rather than by trusting the shared store. The batched settings flush, the `grid_columns` grammar and the About dialog are unchanged.
- 2026-11-05 (v0.0.4 — UI-21 §3.10, UI-22 §3.13, D11 §3.12, UI-27 §3.18) — **UI-21:** the Library section shows the library location — a new whitelisted command `app_data_dir` reading the runtime path `lib.rs` already resolves (DR-111: shown, not configurable; no settings key, no move path, no new capability). Router/client set-equality test extended (AC-41). **UI-22:** Settings section headings drop the uppercase transform and wide tracking for the dialog's sentence-case scale (AC-44). **D11:** the light ramp's accent/warning/danger text roles are retokenized to the approved ≥ 4.5:1 values (DR-120 — the audit's quoted hexes didn't match the shipped values; the user chose the approved values unchanged); a permanent contrast test reads the stylesheet (AC-43). **UI-27:** Settings/About/EmptyState/progress/toast gaps move onto the shared spacing scale (AC-49). Theme resolution, the settings grammar, the batched flush and the About dialog logic are unchanged.
- 2026-11-07 (v0.0.6 — UI-32 ADDED, §3.6; DR-139, DR-145) — **The dark ramp re-authored to the Dracula Classic palette.** Surfaces, borders, text roles, semantic colors, selection/hover grounds and the scrollbar thumb rewritten to the official palette with the measured substitution set recorded in the stylesheet and here (text-tertiary 65 %, accent-quiet 8 %, danger → ANSI BrightMagenta, warning-hover resolves to the base). UI-17's control, the `theme` setting grammar, resolution and `system` following unchanged; the light ramp byte-identical to v0.0.5. New tests: `design-tokens.test.ts` dark mapping + contrast pair table (AC-70), `flowDarkRamp` real-app measured contrast and rendered grounds (AC-71); the existing theme-switch/restart flow passes against the new ramps.
