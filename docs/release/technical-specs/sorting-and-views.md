## Query composition (`src-tauri/src/library/query.rs`)

- `parse_sort(sort, dir)` whitelists the primary sort parameters — `"title"` (default), `"date_added"`, `"size"`, direction `asc|desc`; `parse_sort_secondary(key)` whitelists the **secondary key** (FR-13 as modified in v0.0.2): `"title" | "date_added" | "size"` map to a `SortKey`, `"none"` and any unknown value map to `None`. Nothing user-supplied reaches SQL as a string (no injection surface, R2.2).
- Every list query (search, like-fallback, ids, favorites, category filters) composes one shared ORDER: `ORDER BY d.favorite DESC, <primary> <dir>[, <secondary> <dir>], d.id ASC` — favorites pinned (FR-04/FR-13), title compared `COLLATE NOCASE`, the secondary key **in the primary's direction** (DR-81: one direction control, not two), `d.id` last so the order is total and stable. With no secondary key the clause is byte-identical to v0.0.1 (AC-09's "byte-identical to v0.0.1 ordering" check).
- Title/author/notes/filename search and the LIKE fallback are specified in searching.md; category/favorites filters in categories.md / favorites.md — all share this builder.

## Views (UI-04, UI-08)

- List (virtualized rows, `ui/src/lib/virtual.ts`) and grid (cards) render the same `DocumentDto` stream; switching view does not re-query.
- **`ViewToggle.svelte` was deleted in v0.0.2; `SortMenu.svelte` was deleted in v0.0.3** (UI-08 as modified, R7.4). `components/ViewMenu.svelte` is the single display control for the document area: *List view* / *Grid view* (current mode checked, `aria-checked`), separator, the **Columns** control — *Auto* (checked when the setting is `"auto"`) and a `−` / count / `+` row that shows **the count in effect** and steps from it, disabled only at the bounds `GRID_COLUMNS_MIN = 2` / `GRID_COLUMNS_MAX = 10` (DR-86) — separator, then the two sections `SortMenu` used to render, as the kit's submenus: **Sort by** (the released FR-13 whitelist, current key checked) and **direction**, and **Then by** (None / Title / Date added / Size). The item lists are derived from the same whitelisted keys in `lib/actions.ts` and the same settings store, so the menu cannot offer a key the backend would reject. The toolbar control's accessible name stays the catalog's "View" label and the section headers are the shipped strings — the risk that sorting becomes hard to find was answered inside the menu, not by keeping a second control. The trigger is icon-only with a tooltip (UI-13).
- **Nothing in the backend moved**: `library_search`'s single ORDER builder, `parse_sort`, `parse_sort_secondary`, the `sort` / `dir` / `sort_secondary` keys and their batched persistence are unchanged; the shipped keyboard shortcuts act on the store, not on the control that displays the value (FR-13 untouched).
- `gridLayout(containerWidth, override)` (`lib/virtual.ts`), as modified by DR-99: the column **count** is chosen first — Auto from the 232 px pitch (`CARD_WIDTH + gap`), or the manual 2–10 count clamped to what fits at the `MIN_CARD_WIDTH = 140` floor — and the card **width is then derived** from the container: `floor((containerWidth − (columns − 1) × gap) / columns)`, bounded by `MIN_CARD_WIDTH` and a new `MAX_CARD_WIDTH = 320`. Past the cap the leftover is margin and the grid centers. The shipped `Math.min(CARD_WIDTH, …)` clamp is gone: that is what made a manual count leave slack instead of widening the cards. Pure function, same value at every window width, unit-testable. **Changed in v0.0.4 (UI-19, §3.8):** `containerWidth` is no longer the raw measured area — `DocumentArea` subtracts the 12 px content gutter from both sides (`layout.setAreaWidth(el.clientWidth − 2 × CONTENT_GUTTER)`, `CONTENT_GUTTER = 12` in `virtual.ts`), and the views carry the inset, so rows, cards and toolbar controls share one edge and the last column never touches the window edge (AC-39, measured at 900/1280/1900 px in `flowContentGutter` / `flowWidthMatrix`). The derivation itself is unchanged; only its input is.
- `cardHeight(cardWidth)` and `cellHeight(cardWidth)` (new, §3.10): `10 + coverHeight(cardWidth) + CARD_TEXT_BLOCK (70)`, where `coverHeight` keeps the shipped inner-cover ratio (a `cardWidth − 2` inner cover at 218:309, DR-83). At the shipped 220 px card this reproduces the shipped 389 px exactly — the anchor the derivation must not move — and `cellHeight` adds `CARD_GAP`. `itemSize` for the grid is that derived value, so a row block always equals the cards it contains. Still computed once per resize, never per item: offsets stay computable from the index alone (§5.3.5's purity rule). **Changed in v0.0.4 (D6, §3.4):** the leading 10 px term is gone — `.cover-wrap` no longer pads the cover, the cover fills the card's inner box from its top edge — so `cardHeight(cardWidth) = coverHeight(cardWidth) + CARD_TEXT_BLOCK`, the 220 px anchor still yields 389, and `virtual.test.ts`'s card-height/row-block cases were re-derived to the new formula (AC-35).
- **List metrics changed in v0.0.3** (UI-03 as modified): `ROW_HEIGHT` 48 → **64** and `--row-height` with it; `ROW_LINE` stays 18, so a row carrying two metadata lines is 64 + 36, and `rowHeight(doc)` / the offsets builder keep their shape with a new base constant. The list cover is `ROW_COVER_WIDTH = round(ROW_HEIGHT × 210 / 297)` — 45×64, derived from `ROW_HEIGHT` so the two can never disagree.
- **Row cover enlarged, row gap added — v0.0.7 (UI-03 row facet, §3.12, DR-188/DR-189).** The cover stays derived from the row, one source: new `ROW_COVER_GAP = 8` mirroring the `--row-cover-gap` token (the lockstep rule), `ROW_COVER_HEIGHT = ROW_HEIGHT − 2 × ROW_COVER_GAP`, `ROW_COVER_WIDTH = round(coverHeight × 210 / 297)`. With OQ-45 closed on option B: `--row-height: 88px` / `ROW_HEIGHT = 88` → **51×72 cover centered in the 88 px row with an 8 px gap** above and below against the separator hairlines (the 8 px equals the row's own internal rhythm); a row with author and notes renders 88 + 2×18 = 124 px. `DocumentRow` passes the derived box to the existing `Cover` component; every consumer follows automatically — `rowOffsets` and the viewport bound, the skeleton placeholders, the row-design flow. The released assertions that hard-coded 64/45 were re-derived to 88/51×72, not deleted. **Cover pipeline untouched:** the asset is still 640×905 (`RENDER_TARGET_WIDTH` is not in the display path and not in the cache key) — no re-keying, no regeneration, no backend change.
- **Grid card content changed — v0.0.7 (UI-03, §3.8, DR-183/DR-184).** `DocumentCard.svelte`'s `.meta` span (`formatBytes · formatDate`) and its CSS are **removed**: a card shows title, author when present, the missing badge and the actions — the list row's meta column is the formatters' only remaining consumer (no orphan code). `CARD_TEXT_BLOCK` (70), `cellHeight` and the whole windowing path keep their values; the freed line becomes breathing room inside the fixed block. The actions line, rendered only on hover/focus, gains a ground: `.actions-slot` (card side only) carries `--surface-0` + 1 px `--border-hairline` + `--shadow-overlay` — the app's existing overlay recipe, so the glyphs no longer sit directly on title text (DR-184; per-button chips and a full-width scrim rejected).
- **Card content inset — v0.0.7 (DR-245).** `.card` gains `padding: var(--card-content-pad)` (5 px, new token, mirrored by `CARD_CONTENT_PAD` in `virtual.ts` — the `--row-cover-gap` pattern), and the geometry helpers carry it: `coverWidth(cardWidth) = cardWidth − 2 − 2 × CARD_CONTENT_PAD`, `cardHeight = coverHeight(cardWidth) + CARD_TEXT_BLOCK + 2 × CARD_CONTENT_PAD` — at the 220 px card the cover is 208 wide and the card 375 tall (the released 220→389 anchor re-derives to these; the outer width derivation — Auto pitch 220, 140–320 clamps, column-count-first `gridLayout` — is untouched, so grid density does not change). Purpose: the 5 px frame band carries the selection treatment (UI-38, selecting-documents.md) — at rest the card ground reads as an inner border, when selected the `--selection-tint` + accent border frame the cover. The served asset is the unchanged 640×905 cache entry — no re-keying (the display box never enters the key).
- **Vertical content inset — v0.0.7 (UI-19 MODIFIED, §3.10, DR-186/DR-200).** `DocumentList.svelte` and `DocumentGrid.svelte` join the released `padding-inline: var(--content-gutter)` with `padding-top: var(--content-gutter)` on their `.window` containers, plus `padding-bottom` **on the list window only** (DR-200: measured, `padding-top` alone leaves the last row flush on the status bar; the grid needs none — its windowing unit carries the card's trailing gap). The value is the existing 12 px. The inset is a uniform visual shift of mounted content (every row/card at its computed offset + 12 px): `offsets`, `totalHeight`, `padTop`, the width math (`clientWidth − 2 × CONTENT_GUTTER` — vertical padding does not change `clientWidth`) and the mounted-node bound are untouched; the window function's ≥ 6-item overscan covers the shift mid-scroll. The toolbar/status-bar hairlines stay as released — the gap sits between the hairline and the content.
- **Size display by magnitude — v0.0.7 (UI-36, §3.9, DR-185/DR-208).** `ui/src/lib/format.ts::formatBytes` selects the unit by magnitude through `Intl.NumberFormat` byte-unit formatting (`unitDisplay: "short"`, one decimal base across units — `Intl`'s byte convention, kept): `n < 1_000` → bytes, no fraction digits (`512 B`); `1_000 ≤ n < 999_950` → kilobytes, at most one fraction digit (`2 kB`, `12.5 kB`); `n ≥ 999_950` → megabytes, one fraction digit below 100 000 000 and none from there (`1 MB`, `2.4 MB`, `125 MB`). The 999 950 boundary is where one fraction digit would render `1 000 kB`. `n === 0` → `0 B`. Binary MiB considered and rejected (DR-185): uneven localization, and one app must not mix bases between what it shows and what it sorts on. The rendered value appears in the list row's meta column (the card no longer shows sizes); the sort whitelist and stored sizes are untouched.
- `lib/state/layout.svelte.ts` owns the measured document-area width, the derived Auto count (`areaWidth`, `autoColumns = gridLayout(areaWidth, null).columns`) and — since v0.0.3 — the Select-mode boolean (selecting-documents.md). `DocumentArea` measures into it via a resize effect instead of holding a local `containerWidth`, which is what lets the View menu and the Settings dialog display the effective count.
- **Row internals refined in v0.0.4 (UI-23, §3.14):** `DocumentRow.svelte` reserves a fixed **96 px meta column** (`.meta`, `flex: none`, content right-aligned, `tabular` figures) between the text column and the actions line — the column's left edge and the size figures' right edge are identical on every row whatever the filename length; the text column keeps the existing ellipsis rules and the width-based column drop (§5.3.7: filename at ≤1100 px, meta at ≤900 px) is unchanged. Row height, cover geometry and the actions line are untouched (AC-45).
- **First-paint placeholders, v0.0.4 (UI-28, §3.19):** `components/SkeletonRows.svelte` draws the geometry `virtual.ts` already derives — row blocks at `ROW_HEIGHT`, cover placeholders at `ROW_COVER_WIDTH × ROW_HEIGHT` (45×64), title/meta bars at the real line positions — imported from `virtual.ts`, defining no cover dimensions of its own. When data arrives the content does not move; the shimmer animation is unchanged (AC-50, measured in `flowEmptyAndSkeleton`).
- Virtualization renders only the visible window — off-screen rows are not in the DOM (a fact the UI smoke harness must respect).

## Persistence (DR-44)

- View mode, grid column override, sort key/direction/secondary key and last filter persist in the `settings` table via `app_get_settings` / `app_set_setting`; the UI store (`ui/src/lib/state/settings.svelte.ts`) reads once at startup and writes debounced. Restored on next launch (startup gate in `lib.rs` ensures the first `status_updated` is delivered). Settings keys: `view`, `grid_columns` (`"auto"` or `2..=10`, validated by `is_valid_grid_columns`), `sort`, `dir`, `sort_secondary` (`none|title|date_added|size`), `last_filter` (grammar in categories.md). An invalid stored value is rejected by `set_setting` as `AppError::Validation`, and a corrupt stored value falls back to the default on read.
- **Writes are batched, not per-key (AC-09 fix):** one trailing-edge `debounce` (300 ms) collects every changed key into a `Map<key, value>` and flushes each distinct key once with its last value. A separate debounced function per key silently dropped all but the last write of a tick — changing sort plus secondary plus filter in one action persisted only the last key. Regression test: `ui/src/lib/state/settings.test.ts` (fails against the per-key form, passes against the batch).
