## Counts pipeline (FR-15)

- Single aggregate: `SELECT COUNT(*), COALESCE(SUM(favorite),0), COALESCE(SUM(missing),0) FROM documents` (`library/service.rs`) → `CountsDto { total, favorites, missing }`.
- Emitted as the `status_updated` Tauri event from every mutation (import, delete, relink, rescan, favorite/category changes) via `EventSink` (`src-tauri/src/lib.rs`). A startup gate holds the first emission until the UI's `listen()` has succeeded — otherwise the UI loses the startup counts to a race it usually loses.
- UI, as shipped in v0.0.3 (`components/StatusBar.svelte`): the bar is **conditional** (UI-15). It always renders one quiet document count — `formatCount(counts.total)`, `--text-tertiary`, 12 px, `tabular-nums` — and nothing else by default. The missing-file warning renders only when `counts.missing > 0`; the progress bar only while a job runs; the result count only while a filter or search is active. The three count chips and the Rescan button are deleted, and the `contentinfo` landmark is unchanged. The counts and the rescan control now live in the Browse menu (UI-09, [browsing-and-filtering.md](browsing-and-filtering.md)). The sidebar Favorites row count that v0.0.1 described is gone with the sidebar (v0.0.2). No component computes counts locally: every number on screen comes from the `status_updated` payload, and the frontend never caches or derives one.
- **The count text gained its label — v0.0.7 (UI-15 MODIFIED, §3.15, DR-210).** The quiet number renders as the labeled plural text — `t('status.documents.' + (count === 1 ? 'one' : 'other'), { count })` → "1,234 documents" / "1 document" — through two new catalog keys following the released plural-count mechanism (UI-16's placeholder counts, the `plural-count` test's pattern), the count through the existing number formatting. The missing-file warning likewise reads "3 documents missing" (`status.missingFiles.one/other`, the DR-211 wording). `.status-count` styling (tertiary 12 px, `tabular-nums`), the `status_updated` source (library-wide — FR-15's invariant), and every other status-bar row are unchanged.
- **Terminology — v0.0.7 (DR-211, copy correction).** The catalog speaks of library items as **documents** everywhere; "file" remains only where the physical file on disk is meant (a missing entry's last known location, relinking to a new location, "no such file" errors). Value-only edits in `ui/src/lib/i18n/en.ts` — key identifiers unchanged: `browse.missing` → "Missing documents", `browse.rescan` → "Rescan documents", `status.missingFiles.*` → "{count} document(s) missing", the missing empty-state, `relink.title`, `toast.relinked`, `toast.rescanFound.*`, `toast.rescanRestored.*` and the related strings follow the same audit (recorded in DR-211). No component, key identifier or behavior changed.

## Job progress

- `library_job_progress` events carry `JobProgress` for import batches and the cover pipeline → import progress UI. The contract is the one shipped in v0.0.1: throttled (every 25 completions + final drain). v0.0.5 (D17, DR-134) parallelized the pipeline behind the counter — one render worker + N encode workers sharing one `ProgressTracker` whose gate keeps the event stream monotonic — the event stream itself is unchanged ([covers.md](covers.md)).
- **v0.0.4 (D10, §3.11):** `ProgressBar.svelte`'s fill keeps `width: 100%` and carries the progress in `transform: scaleX(var(--p, 0))` with `transform-origin: left`, transitioned as `transform var(--duration-hover) var(--ease)`. The old declaration named `--duration-base`, a token defined in neither ramp — the transition was invalid at computed-value time and the fill jumped between job updates. Bar height, colors and `role="progressbar"` semantics unchanged (AC-42: computed style names `transform` with a non-zero duration; width stays 100% through a job). **UI-27 (§3.18):** the bar+label row gap moves to the shared 8 px value. The three progress strings — *Importing…*, *Checking files…*, *Generating covers…* — keep their ellipsis by UI-20's design (work under way, not a target); `coverage.test.ts` enforces the split mechanically (AC-40).

## Errors (`src-tauri/src/error.rs`)

- `AppError` variants (TitleEmpty, Validation, CategoryNameDuplicate, CategoryNotFound, DocumentNotFound, MissingFile, NotPdf, PathTaken, Io, Db, Internal) map to `AppErrorPayload { kind, message, document_id }` — typed, user-presentable, no raw strings across the boundary (R2.1).
- UI (`ui/src/lib/state/feedback.svelte.ts`): `reportError(payload, action?)` renders an error toast, optionally with an action button (**Relink** — without the ellipsis since v0.0.4, UI-20 — on MissingFile, retry on a failed file deletion — opening-and-deleting.md). Field-level errors (empty title) render inline in the form instead.
- Success toasts are plural-aware (`notify(PluralBase, count)`, DR-55): "1 document imported" / "N documents imported".
- **v0.0.4 (UI-27, §3.18):** the toast stack's inter-toast gap moves 10 → 8 px and its vertical padding 10 → 12 px — the shared 4 px scale values, no new token (AC-49 measures every gap/margin inside the stack as a multiple of 4).
- **v0.0.4 (UI-29, §3.20):** the empty-library state renders its keyboard hint as keycaps — `empty.library.keys` ("Ctrl+I") is its own catalog value, split on `+` and drawn as `<kbd class="keycap">` chips (monospace, `--surface-2` ground, hairline border, 6 px radius) between unchanged words. The string stays in i18n (R4.1); the coverage test passes with the new key (AC-51).
