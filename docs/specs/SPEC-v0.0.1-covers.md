# Feature spec: Cover thumbnails — v0.0.1

**Parent:** [SPEC-v0.0.1.md](SPEC-v0.0.1.md) · **Slug:** `covers` (docs/released pair) · **Lifecycle:** inherits the parent's registry status; frozen with the parent.

## Requirements

| ID | Requirement | Status |
|---|---|---|
| FR-16 | **Cover thumbnails.** Every document displays a first-page cover in list rows and grid cards. Covers are generated at import, regenerated by Rescan when the file changed or the cover is absent, cached in the app-data directory keyed by path+size+mtime, and removed when the library entry is removed. Unrenderable pages fall back to a generic PDF glyph. Covers are in-app thumbnails only — documents still open externally (DR-04 unchanged). | **AGREED** (DR-16, DR-17) |

Depends on: parent §6 (`pdfium-render` rasterization, PNG cache), NFR-02 (background pipeline, non-blocking). Interacts with: SPEC-v0.0.1-importing-pdfs.md (jobs enqueued at import), SPEC-v0.0.1-missing-files-relinking.md (regeneration on rescan), SPEC-v0.0.1-sorting-and-views.md (display in both views).
